# Codex 0.153.4 and GPT-6 Integration Design

Date: 2026-09-05
Status: Approved

## Goals

- Update the backend-facing Codex library behavior from the current 0.149.x
  baseline to the official 0.153.4 release compatibility level.
- Add first-class `gpt-6-astra` support through the same library path used by
  the backend, rather than implementing a TUI-only model entry.
- Preserve code-mod's custom providers, GPT-5.6 agents, settings flows, and
  other fork-owned behavior.
- Preserve all pre-existing uncommitted operator changes in the worktree.

## Non-Goals

- Do not replace the complete code-mod workspace with the OpenAI Codex
  0.153.4 source tree.
- Do not remove or rename existing model presets.
- Do not make GPT-6 the default model unless the active remote model catalog
  selects it as the default.
- Do not add compatibility flags or retain obsolete fallback implementations.

## Architecture

The integration will use a selective runtime-parity port. The official
`rust-v0.153.4` source is the behavioral reference, while `code-rs` remains the
executable backend and library implementation owned by code-mod.

The implementation will update four connected layers:

1. The embedded client version and minimum-version compatibility logic.
2. The internal model catalog consumed by backend defaults and compatibility
   checks.
3. Shared protocol and configuration types required to represent GPT-6
   metadata and reasoning levels without lossy conversion.
4. Model selection, model-family derivation, request construction, and
   app-server conversions used by backend consumers.

The existing `codex-rs` directory remains a read-only upstream reference. Only
the authoritative catalog data needed by the code-mod runtime will be refreshed
there; Rust implementation changes will be made under `code-rs`.

## GPT-6 Contract

The backend MUST recognize the official model slug `gpt-6-astra`.

The built-in fallback preset MUST expose:

- display name `GPT-6-Astra`;
- description matching the official 0.153.4 catalog;
- default reasoning effort `low`;
- supported reasoning efforts `low`, `medium`, `high`, `xhigh`, `max`, and
  `ultra`;
- default text verbosity `low` with configurable supported verbosity;
- text and image input support;
- extended-context behavior consistent with the official catalog;
- minimum compatible client version `0.153.0`.

Remote model metadata remains authoritative when available. The built-in
preset provides deterministic behavior when the remote catalog is unavailable
or incomplete.

## Compatibility

`ultra` reasoning MUST round-trip across configuration, protocol serialization,
app-server responses, model selection, and request construction. Existing
reasoning levels MUST retain their current serialized values and behavior.

The embedded local-build version MUST be `0.153.4`. Model-specific wire
compatibility MUST continue clamping older or development version strings to a
model's advertised minimum client version.

Existing GPT-5.6 presets and provider-specific model prefixes MUST continue to
resolve without behavior changes. GPT-6 family detection MUST accept the
canonical slug and provider-prefixed forms that already use the repository's
normal model canonicalization path.

## Error Handling

- Unknown future reasoning values MUST fail clearly at typed configuration or
  protocol boundaries instead of silently mapping to a lower effort.
- A malformed internal model catalog MUST retain the existing safe fallback
  behavior and MUST NOT prevent the CLI from starting.
- Remote catalogs that omit GPT-6 MUST fall back to the built-in preset.
- Remote metadata MUST NOT erase code-mod-specific model presets.

## Verification

Regression coverage will be added before production changes for:

- the embedded version reporting `0.153.4`;
- parsing the refreshed catalog and reading GPT-6's minimum client version;
- `ultra` reasoning serialization and conversion in both directions;
- GPT-6 picker presence, ordering, default effort, and supported efforts;
- GPT-6 model-family derivation and extended-context behavior;
- provider-prefixed GPT-6 model canonicalization;
- preservation of existing GPT-5.6 presets.

After focused tests pass, the required final verification is
`CARGO_BUILD_JOBS=1 ./build-fast.sh`. No additional completion lint or format
commands will be run unless required to diagnose a failure.
